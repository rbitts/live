# 연속 요리 영상으로 작업 진행과 회상 검증

사용자 요구(2026-10-14)는 전체 요리 과정의 주변 상황을 관찰하다 손질 완료 후
다음 일을 먼저 안내하고, 다른 사람과 대화하다 돌아온 사용자의
“뭐 하고 있었더라?”에 완료한 단계와 이어 확인할 일을 설명하는 것이다.
단순 사물 회상이나 타이머 전달만으로 이 요구를 통과했다고 평가하지 않는다.

## 선정 영상과 근거

첫 과제는 EPIC-KITCHENS `P18_03`의 샐러드 준비다. 전체 원본은427.435초,
1920×1080, 측정 평균 프레임률60000/1001이며 공식 EPIC-100 행동 주석113개가 있다.
샐러드 채소/건포도 담기 → 오이 씻기·말리기 → 자르기·담기 → 양념 → 섞기가 이어진다.
중간에 냉장고·설거지·다른 음식의 오븐 작업도 있어 무관한 행동에 침묵해야 한다.
샐러드 이외 요리의 익힘·안전·완료는 이 영상으로 추정하지 않는다.

원본, 주석, 해시와640×360/~15fps 무음 재생본은 `.runtime/task-video/`에 둔다.
재생본은 처음부터 끝까지 원래 순서와 속도를 유지하며 반복·장면 재조합이 없다.
원본 음성은 보존하지만 재생 입력에서는 빼고 별도 모의 사용자 PCM을 사용한다.
행동 주석과 정답 시각은 평가자만 사용한다. 앱은 recipe 단계, 실제 사진과
실제 ASR만 받으며 주석 시각으로 단계 완료나 알림을 실행하지 않는다.

원본은 EPIC-55 test, EPIC-100 action recognition validation에 속한다.
기존 로컬 OJT(P01/P06/P32)와 참여자가 다르지만 이번 개발 과정에서 확인했으므로
새로운 blind test라고 부르지 않는다. train/calibration/FT로 가져오지 않았다.
CC-BY-NC-4.0은 원본 배포 README와 주석 파일의 개별 license에 따른다.
출처·변환·원본과 재생본 SHA256은
[미디어 기록](../reports/cooking-task-media-manifest.json)에 남긴다.

## 세션 작업 기억과 개입

`CookingSession`은 기존 요리 계획의 최대8단계, 완료 출처, 현재 단계,
최근4개 모델 관측, 보류한 안내 하나를 유지한다.
사용자가 확인한 완료와 영상으로 추정한 완료를 구분한다.
일반 대화/타이머 목표가 바뀌어도 요리 진행 상태는 유지한다.
세션 종료·기억 삭제·opt-out은 이 상태를 삭제한다.

영상 진행 관찰은 요리 메뉴의 명시적 선택이다. 진행 동작을 관측한 뒤,
서로 다른 최신 프레임 두 개(최소500ms 간격)의 완료 판단이 있어야 진행을 바꾼다.
같은 사진의 재사용, 늦은 revision,15초 초과 결과, 불확실/가려진 장면을 거부한다.
작업을 다시 관측하거나 영상 시각/소스가 바뀌면 옛 완료 후보로 재개하지 않는다.
서로 다른 프레임과 두 번의 판정은 소프트웨어 중복 방지이며 모델 판단의
정확성을 보장하지 않는다. 실제 장면과 응답의 별도 검수가 필수다.

2026-10-14 사용자 지시에 따라 사물/동사별 질문으로 단계 판정을 우회하던
후보를 제거했다. 관측 phase/evidence는 실제 Qwen 모델 출력을 그대로 받으며,
형식/시간/세션 검사를 통과하지 않은 결과를 정답으로 보정하지 않는다.
모델의 작업 분리·완료 인식 약점은 [LoRA 학습 계획](task-lora-plan.md)에 기록한다.
온도·익힘·위생을 영상으로 확정하지 않는다.
작업 관측은 작은 손 움직임도 놓치지 않도록 최신 프레임을 주기적으로 검사하며,
무관한 장면 변화 알림의 기존 변화 감지 정책과 분리한다.
추론은 하나씩 처리하고 영상/마이크 입력은 계속 수집한다.

“잠깐 옆 사람이랑 얘기하고 올게”는 명시적인 안내 보류다.
그동안 일반 발화를 도구 명령/AI 질의로 실행하지 않으며 관측은 가능한 동안 계속한다.
“돌아왔어. 뭐 하고 있었더라?”는 저장된 진행과 다음 확인할 단계를 회상한다.
화자 식별이나 AI를 향한 발화의 자동 구분은 구현하지 않았다.
안내 재생이 중단되면 보류한 내용을 유지하고, 실제 AudioTrack 재생 완료 후 전달로 기록한다.
회상은 마지막 확인한 상태이며 관측하지 못한 추가 진행을 완료로 만들지 않는다.

## 검증 분리

- CPU 상태 검사: 완료 근거, 중복/오래된 관측, 안내 보류, 다른 대화 후 회상,
  source rewind, opt-out/reset, 조건 질문 범위를 검증한다.
- `CookingTaskInstrumentation`: 해시가 고정된 실제 장면을 시간 순으로 실제 모델에
  전달한다. 일부 이전 단계는 fixture에서 사용자가 확인한 상태로 초기화한다.
  모델 판단 진단이며 전체 ambient replay/ASR 합격이 아니다.
- `AmbientCookingInstrumentation`: 전체 MP4를 실제 속도로 재생하며 모의 PCM→VAD→
  실제 ASR→작업/관측→TTS→AudioTrack 경로를 사용한다. 카메라 관측과 음성은 동시에 간다.
  씻기/손질 완료를 script가 강제로 진행시키지 않는다. 입력은 실제 모델 결과와 ASR뿐이다.
  타이머 회화형 정정, 다른 사람과 이야기하는 동안 침묵, 돌아온 뒤의 회상을 기록한다.
- 사람의 마이크/다른 화자/주방 소음/실제 카메라/음향·발열 및 범용 조리 정확도는 별도다.

모델·기기별 실제 측정과 실패는 [선정·검증 보고서](../reports/cooking-task-selection.md)에 기록한다.
이 경로는 Qwen **system duplex**이며 MiniCPM native duplex acceptance를 대신하지 않는다.
