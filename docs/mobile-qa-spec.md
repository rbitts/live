# Galaxy S 오프라인 물체 위치·최근 관측 QA

2026-10-12 사용자 결정: 최신 Galaxy S, 물리 RAM 12GB 상한, 완전 온디바이스, 물체 위치·최근 관측 기억 QA, 비상업 연구·학습 데모. 현재는 일반 양자화를 수행하며 NPU/Qualcomm 전용 최적화는 후속이다. 이 문서는 학습 데이터 설계와 평가 시나리오이며 실제 수집 데이터나 모델 평가 결과가 아니다.

## 첫 제품 범위

- 모바일 카메라·마이크로 관측하고, 한국어 질문에 한국어 음성으로 답한다. ASR·VLM·TTS·기억은 모두 로컬이다.
- 현재 관측은 유효한 최신 프레임 근거다. 과거 관측은 그 시각에 보였다는 근거이며 현재 위치로 승격하지 않는다.
- 물체의 화면 기준 왼쪽/오른쪽, 책상 위/의자 아래 같은 시각적 관계를 답한다. 카메라 자세/깊이 근거 없이 세계 좌표, 거리나 숨겨진 물체의 위치를 추정하지 않는다.
- 같은 종류가 여러 개이면 색·형태·주변 물체를 이용해 구분하거나 다시 묻는다. 보지 못한 대상/가림/카메라 꺼짐은 답변 유보가 정답일 수 있다.
- 최근 관측은 세션 범위다. 완료 대화/프레임 수와 timestamp를 제한하고 reset/앱 종료 시 폐기한다. 지속 저장·상시 객체 추적은 별도 확장이다. 샘플링 간격/보존량은 메모리와 기억 성능을 측정해 정한다.
- LoRA/QAT의 대상은 우선 VLM으로 잡는다. 기억 내용 자체를 가중치에 외우게 하지 않고, 입력된 현재/과거 근거를 구분해 답하는 행동을 학습한다.

## 평가 시나리오

| ID | 준비와 질문 | 기대 행동 / 실패 조건 |
|---|---|---|
| QA01 | 빨간 컵을 책상 왼쪽에 놓고 “컵은 어디 있어?” | 현재 이미지에 근거한 위치 답변 |
| QA02 | 빨간 컵과 흰 컵을 다른 곳에 놓고 빨간 컵 질문 | 요청한 물체를 구분; 다른 컵 위치면 실패 |
| QA03 | 같은 색 컵 여러 개를 놓고 모호하게 질문 | 근거 없이 하나를 선택하지 않고 구분 질문 |
| QA04 | 컵을 왼쪽에서 오른쪽으로 옮긴 뒤 현재 위치 질문 | 새 관측을 우선; 과거 위치를 현재로 말하면 실패 |
| QA05 | 컵을 본 뒤 화면 밖으로 치우고 “아까 어디 있었어?” | 마지막 관측 위치를 과거 표현과 함께 답변 |
| QA06 | QA05 상황에서 “지금 어디 있어?” | 현재 위치는 확인 불가, 마지막 관측은 별도로 설명 |
| QA07 | 카메라를 끄거나 최신 프레임이 만료된 뒤 현재 위치 질문 | 과거 프레임을 현재 증거로 사용하지 않음 |
| QA08 | 한 번도 보지 않은 물체의 위치 질문 | 관측 근거 없음을 밝힘 |
| QA09 | 기억 삭제 또는 앱 종료/재시작 후 이전 물체 질문 | 이전 세션의 위치·선호가 남지 않음 |
| QA10 | 답변 재생 중 “아니, 흰 컵”으로 정정 | 즉시 재생 중단, 입력 유지, 이전 응답의 재생 재발 없음 |
| QA11 | 카메라를 회전하거나 시점을 바꾼 뒤 상대 위치 질문 | 현재 시점 기준으로 답하고 과거 화면 좌표와 혼동하지 않음 |
| QA12 | 모델을 로컬 설치한 후 통신 차단·앱 완전 재시작 | 새 음성/영상으로 위 시나리오 수행; 서버/로그인/온라인 다운로드 의존 시 실패 |

QA01~11은 실제 모바일 데이터와 독립된 평가 세션으로 수행한다. QA12는 canned 답변/캐시 재생으로 통과할 수 없도록 모델 설치 후 새 물체 배치와 새 발화를 사용한다. 비행기 모드만 켜고 Wi-Fi가 남아 있지 않도록 Wi-Fi·모바일 데이터 차단도 확인한다.

## 데이터와 채점

- 기존 JSONL의 `group_id`, 이미지 `view`, `captured_at_ms`, `question_at_ms`를 사용한다. `prompt`와 `response`에 관측 시점/근거가 드러나도록 사람이 검수한다.
- 같은 촬영/장소/사람의 근접 프레임을 학습과 test에 나누지 않는다. 실제 test는 합성 데이터와 분리해 고정한다.
- 기록할 지표: 물체 식별/위치 관계 정답률, 최신 관측 우선률, 현재·과거 혼동률, 근거 없는 현재 위치 단정률, 답변 유보 정확도. 한국어 ASR 오류와 VLM 판단 오류를 분리하기 위해 같은 질문의 텍스트 입력도 비교한다.
- 정답 문구의 단순 일치만 사용하지 않는다. “책상 왼쪽”과 “왼쪽 책상 위”처럼 의미가 같은 답을 rubric으로 검수한다. 정답 레이블·오류 분류와 실제 모델 출력은 평가 보고서에 함께 보존한다.
- base/LoRA/merged/PTQ/QAT/exported는 같은 frozen test와 decoding 설정으로 비교한다. 목표 정확도 수치는 데이터 난도와 base 성능을 측정한 후 정한다. test를 calibration이나 학습에 재사용하지 않는다.
- 공개 GQA/VISOR 소규모 데이터는 확보했지만 한국어 정답의 사람 검수와 사용자 촬영 데이터 수집 동의는 아직 확보되지 않았다. 이 시나리오 정의가 사용자 영상 수집이나 녹화를 자동 승인하지 않는다.
- 공개 학습 데이터는 [GQA/VISOR 가공 계획](mobile-datasets.md)을 따른다. 2천 pilot/2만 본 실험 목표와 답변 유보 파생본을 구분하고, source 공식 분할과 participant/image 그룹을 보존한다. 이 조합은 VLM FT용이며 ASR/TTS 학습셋은 아니다.

## 첫 실행 순서

1. 연결한 Galaxy S의 실제 SKU/OS/SoC/RAM/지원 backend를 기록한다. 12GB는 기기 전체의 확정 상한이며 앱이 모두 사용할 수 있는 RAM이라는 뜻은 아니다. 초기 앱 작업 예산 약 8GB를 검증한다.
2. ASR, VLM text+image, TTS+codec를 각각 변환하고 오프라인 실제 출력을 확보한다. 현재 TTS CustomVoice/Sohee 지원 여부를 별도로 확인한다.
3. 세 모델의 동시 적재/peak RAM/초기화 비용/재생 처리율을 CPU 및 지원 GPU backend에서 측정하고 상주·지연 로드 정책을 정한다. NPU 가속/Qualcomm 전용 양자화는 후속이다.
4. 고정 base로 실제 데이터의 기준 성능을 측정하고 LoRA 학습 범위/데이터와 QAT 규격을 정한다.
5. 앱에서 통신 차단 cold start, 5분 Live, 10회 끼어들기 및 QA01~12를 검증한다. 기존 `docs/verification.md`의 지연 목표와 소프트웨어/모델/human 검증 구분을 유지한다.

PC 대체 검사와 실패: [mobile-pc-validation.md](../reports/mobile-pc-validation.md). QA03 모호한 대상은 실패했고, QA09 모델 단독 무관측 추측은 앱의 명시적 근거 없음 정책으로 차단했다. 실기기 acceptance와 구분한다.
