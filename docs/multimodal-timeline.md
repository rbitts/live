# 음성·영상·텍스트 공통 시간축 설계

2026-10-14. **설계 규약이며, 전체 구현 완료를 뜻하지 않는다.** Android 0.22의 샘플 영상·발화 끝 anchor 정렬은 부분 구현이며,
기기 시계·공통 사건 전체 구현은 아니다. 기존 음성 → 인식 텍스트 → 응답과 재도입된 영상에 같은 규약을
부분 적용한다. 검색 메모리와 별개로, 진행 중 작업의 근거와 다음 행동을 연결한다.

## 현재 구현과 남은 차이

| 항목 | 현재 | 이 설계에서 추가할 것 |
|---|---|---|
| 공통 작업 메모리 | 어댑터가 단조 시각을 전달; generation/revision/출력 취소 및 도구 receipt 관리 | 사건의 원본 시간 구간과 인과 관계 |
| 음성 | 16kHz PCM, 수집 sample counter, 발화/부분 인식 callback 시각, ASR turn ID | 구간별 sample 범위와 수집 시계 연결 |
| 인식 텍스트 | turn 단위 부분/확정 결과와 stale 결과 거부 | 원본 음성 구간 참조, 가설 버전; 인식 완료 시각과 분리 |
| Android 영상 | 캡처 요청 직전 단조 시각 `issued`를 프레임 `at`로 전달, 3초 freshness, 현재/과거 구분 | 센서 시각의 출처·오차, 발화 시간에 맞춘 프레임 선택 |
| 웹 영상 | capture ticket 기반 보수적 freshness | 클라이언트/서버 시계 매핑과 공통 사건 참조 |
| 출력 | epoch 취소, 실제 AudioTrack 재생 위치로 전달 완료 판정 | 답변 텍스트 구간 ↔ 출력 PCM ↔ 실제 재생 구간 연결 |

Android의 `issued`는 요청부터의 지연을 포함하는 보수적인 시각이다.
현재 프레임 시각을 센서 노출 시각으로 보장하거나, ASR 텍스트에 단어별 시간이
있다고 간주하지 않는다. 기존 freshness 검사는 동기화 정확도 검증이 아니다.
현재 모바일 `liveQuestion(at)`의 `at`는 음성 처리 경로에서 전달된 시각이며,
사용자가 특정 대상을 언급한 순간을 나타내는 공통 계약은 없다.

## 사건의 공통 봉투

모든 어댑터는 아래 의미를 보존한다. 구현 언어나 직렬화 형식은 각 경로가 정한다.

| 필드 | 의미 |
|---|---|
| `session_id`, `generation` | 세션과 기억 초기화 경계 |
| `event_id`, `stream_id`, `sequence` | 중복 제거와 스트림 내 순서 |
| `kind`, `source` | 음성/영상/입력 텍스트/도구/응답/재생 및 실제·모의 출처 |
| `clock_id`, `source_start`, `source_end` | 원본 장치 시계의 반열린 구간 `[start,end)`; 순간 사건은 별도 point 표기 |
| `start_us`, `end_us`, `uncertainty_us` | 세션 단조 시간축으로 변환한 구간과 오차; 알 수 없는 오차는 unknown |
| `received_at_us`, `processed_at_us` | 수신·처리 시각. 원본 사건 시각을 대체하지 않음 |
| `turn_id`, `task_id`, `revision`, `output_epoch` | 대화·작업·행동 최신성·출력 취소 경계; 해당 없는 필드는 생략 |
| `parent_ids`, `payload_ref` | 원본 미디어/명령/결과와 연결; 제한된 세션 저장소 참조 |

단위는 정수 마이크로초지만 정밀도를 보장하는 뜻은 아니다. wall-clock은 사람에게
날짜를 표시할 때만 사용한다. 단조 시간은 서로 다른 장치나 재부팅 사이에서 직접
비교하지 않는다. 같은 기기도 센서별 timebase가 같다는 확인 없이 혼합하지 않는다.

시계 매핑은 offset, 필요 시 drift, 측정 오차와 유효 구간을 가진다. 원격 경로는
왕복 측정 등으로 매핑을 추정하고 그 불확실성을 보존한다. 매핑이 없거나 오차가
정책 범위를 넘으면 정렬 불가로 처리한다. 재접속·시계 재설정은 새 clock 구간을
만들며, 원본 시각은 보존한다. 수신 시각밖에 없으면 그 사실을 명시한다.

## 각 입력과 출력의 연결

1. **음성**: PCM 청크마다 sample rate, 시작 sample index, sample count와 수집
   시각 anchor를 기록한다. 드롭·route 변경·실제/모의 입력 전환은 discontinuity로
   남긴다. 무음을 잘라 만든 발화도 원본 sample 범위에 연결한다. 모의 입력은 실제
   인식 경로에 주입된 시각이 기준이며, 모니터 스피커 재생 시각은 별도 사건이다.
2. **인식 텍스트**: partial과 final은 같은 `turn_id`와 음성 범위를 참조한다.
   `hypothesis_version`, `is_final`로 교체 관계를 표현한다. 최종 인식만 작업 의도를
   확정한다. 단어 시간이 실제 제공되지 않으면 발화 전체 범위까지만 안다고 표시한다.
3. **영상**: frame ID, 수집 시각/노출 구간, 시계 출처 및 오차를 가진다. callback
   시각만 있는 경로는 이를 센서 시각으로 포장하지 않는다. 영상이 꺼졌으면
   `unavailable`이며 과거 프레임으로 현재 화면을 대신하지 않는다.
4. **직접 입력 텍스트**: 전송 시점을 point 사건으로 기록한다. 음성에서 나온
   텍스트와 구분하며, 작성 시작 시각이나 읽은 시각을 추정하지 않는다.
5. **도구**: 요청·시작·진행·종료·후속 안내는 같은 실행 ID와 원인 입력을 참조한다.
   타이머는 설정 시각과 deadline을 별도로 가진다. 결과 도착이 늦어져도 실행 당시
   사실과 현재 작업에 대한 유효성은 구분한다.
6. **응답**: 텍스트 segment ID에 생성 PCM sample 범위를 연결하고, 재생 시작/진행/
   중단/완료 사건을 별도로 기록한다. 큐 등록이나 생성 완료는 전달 완료가 아니다.
   TTS 정렬 정보가 없으면 문장 내부의 어느 단어까지 들렸는지 추정하지 않는다.

## 정렬과 메모리 주입

입력 수집은 정렬이나 추론을 기다리지 않는다. 제한된 timeline 버퍼에서 입력 확정
시점에 **정렬된 입력 묶음**을 만든다. 여기에는 확정 텍스트, 원본 발화 구간,
선택한 시각 근거와 시간차·오차, 현재 목표/조건, 도구 상태, 미전달 안내가 들어간다.
행동 lease는 이 묶음의 generation/revision과 근거 event ID를 참조한다.

“이거 어떻게 해?”가 10–12초에 발화되고 ASR가 15초에 끝났다면 15초 화면을
자동 선택하지 않는다. 단어 시간이 없을 때의 기본 anchor는 발화 끝 12초이며,
전체 발화 구간을 불확실성으로 보존한다. 해당 구간의 장면 변화가 크면 한 프레임을
정확한 지시 대상으로 단정하지 않고 확인한다. 단어 시간이 있으면 지시 표현의
구간을 anchor로 사용할 수 있다.

프레임 선택은 anchor 이전/구간 내 실제 관측을 우선하며 최대 시간차와 시계 오차를
함께 검사한다. 미래 프레임을 현재 질문의 과거 근거로 소급하지 않는다. 기준 밖이면
현재 근거 없음으로 처리하거나 새 관측을 요청한다. 과거 기억은 관측 시각을 붙여
별도 제공한다. 기존 3초 제한은 유지할 수 있는 상한일 뿐, 세밀한 동기화 허용 오차가
아니다. 실제 허용 시간차는 영상 FPS·용도별 시험 후 확정한다.

공통 메모리는 선택된 근거와 사실을 저장한다. 모든 raw media를 프롬프트나 장기
메모리에 넣지 않는다. 다음 행동 직전과 텍스트/PCM 공개 직전에 현재 lease를 다시
검사한다. 사용자가 말하는 동안 도구가 끝나면 사실만 반영하고, 확정 입력으로
조건이 바뀐 뒤 최신 상태에 맞는 안내를 스케줄링한다.

## 늦은 사건, 끼어들기, 버퍼

- 스트림 sequence와 event ID로 중복·순서 역전을 처리한다. 제한된 지연 허용 구간
  안에서만 정렬 후보를 기다리며, 무제한 대기는 없다. 모달리티별 watermark와
  deadline을 두되, 영상이 꺼졌거나 끊겼을 때 전체 진행을 막지 않는다.
- 이미 확정한 행동의 근거는 뒤늦은 사건으로 조용히 덮어쓰지 않는다. 늦은 사실은
  이력 또는 새 수정 사건으로 남기고, 필요하면 새 revision에서 행동을 재평가한다.
  취소된 epoch의 텍스트/PCM은 되살리지 않는다.
- 끼어들기 감지는 정렬 완료 전에 즉시 재생을 비우고 epoch를 바꾼다. 중단 시각과
  확인된 재생 sample 범위를 남긴다. 단어 정렬이 없으면 기존처럼 미전달 문장을
  통째로 다시 안내하며, 출력 중단과 도구 취소는 별개다.
- raw PCM/JPEG 버퍼에는 시간·개수·bytes 상한을 모두 둔다. 근거가 퇴거되면 참조를
  unavailable로 표시한다. 메타데이터도 상한을 가진다. 값은 실제 자원 시험으로
  정하며, 기존 미디어 제한을 확장하려면 별도 용량 검증이 필요하다.
- raw media는 기본 세션 한정이다. 종료/기억 삭제로 폐기하며 녹음 보관이나 영구
  개인화는 이 설계에 의해 자동 허용되지 않는다.

## 구현 순서와 수용 조건

1. 현재 음성·텍스트 경로에 공통 사건과 PCM↔ASR 연결을 추가한다. 기존 작업 메모리
   호출은 어댑터에서 연결하고, timestamp가 없는 입력은 unknown으로 남긴다.
2. 정렬 묶음과 근거 참조를 모델 문맥/행동 lease에 연결한다. fake clock 시험으로
   지연·역전·취소·시계 재설정·중복·버퍼 상한을 검증한다.
3. 영상 재도입 때 시계 출처와 제한된 프레임 버퍼를 연결한다. ASR 지연 중 장면이
   바뀌는 경우, 오래된/누락된 영상, FPS 저하를 실제 기기에서 검증한다.
4. 출력 segment/PCM/재생 사건을 연결하고 끼어들기 후 미전달 안내를 검증한다.

필수 사례: 늦은 ASR와 장면 전환, 역순 프레임, 시계 offset/drift/reset, 영상 off,
텍스트와 음성의 동시 입력, 발화 중 도구 완료 및 목표 변경, 오래된 epoch의 결과,
모의 입력 모니터 지연, 부분 재생 중 끼어들기, 메모리 압박과 raw 근거 퇴거.
소프트웨어 시험과 실제 센서 동기화/사람의 Live 확인은 따로 보고한다.
현재의 음성 5회 반복 시험은 이 멀티모달 정렬 구조의 수용 시험을 대신하지 않는다.


## 0.22 구현 범위 (2026-10-14)

샘플 MP4 실제 재생과 2fps 미리보기 복사 입력, 마지막 유성 PCM 처리 시각을
기준으로 하는 8프레임/4MiB/4초 ring 선택, ASR 전에 고정한 단일 프레임 근거를
구현했다. 선택은 anchor 이전 최대 3초이며 ASR가 늦어도 새 프레임으로 교체하지
않는다. 영상 off/reset/source 변경은 현재 근거와 늦은 결과를 거부한다.
`Frame.source`와 근사 `sourceMs`는 샘플/카메라 출처를 구분한다.

미리보기 복사 요청·PCM 블록 처리 시각의 센서/표시 지연은 unknown이다. raw sample
구간→공통 event_id, 단어별 시간, 원격 clock offset/drift, 발화 내부 급격한 장면
전환 판정, 출력 단어↔PCM 정렬은 여전히 후속 범위다. 이 한계를 포함한 실측은
[영상·음성 재현 보고서](../reports/android-video-replay-validation.md)를 따른다.
