# 같은 음성 시나리오 반복 측정 — 2026-10-14

**5회·30개 발화를 모두 측정했다. 제어 흐름은 반복해서 동작했지만,
인식과 일반 답변의 고정적인 실패 때문에 전체 과업 성공은 0/5였다.**
성공률을 높이기 위한 제품/모델/프롬프트 수정이나 실패 발화 대체는 하지 않았다.

## 측정 조건

- 사전에 작성한 [고정 계획과 판정 기준](repeated-voice-protocol.md)을 적용했다.
- SM-X926N / Android16 / MT6989·Mali-G720, Android0.18-working-memory.
  매 회 세션 기억만 초기화하고 동일 모델 프로세스에서 순차 실행했다.
- 설치된 오프라인 `ko-KR-language` 합성 입력을 실제 속도 PCM으로 넣고
  Capture/VAD→실제 Qwen ASR→실제 타이머 또는 VLM→AudioTrack을 사용했다.
  전사 원문이나 타이머 완료를 직접 주입하지 않았다.
- 총 실행 310.439초, 실제 캡처 4,590,720 samples(16kHz).
  매 회 초기화했으므로 5분 연속 단일 세션 acceptance로 대체하지 않는다.
- 입력 문장 6개를 각각 5번 반복한 단일 합성 화자 측정이다. 새로운 사람·문장·소음
  환경에 대한 일반 정확도가 아니며, 서로 독립인 화자 표본으로 취급하지 않는다.

음성을 끝까지 출력한 것과 질문에 제대로 답한 것도 별도다.

| 회차 | 샐러드 첫 글자 | 샐러드 첫 PCM write | 일반 답변 재생 완료 | producer starvation |

| 1 | 2,928ms | 3,970ms | 완료 | 0 |

| 5 | 2,717ms | 3,755ms | 완료 | 0 |

첫 write 중앙값 **3,755ms**, 최댓값 **3,970ms**다. 앱이 기록한 응답 시점 기준이며
mock 음성 합성 전체 시간이나 실제 귀에 들린 순간은 아니다. 5개 값으로 제품 p95를
보장하지 않는다. 타이머 결과는 변경 확인 뒤 약19.98–20.52초에 관측됐다.
재생 중 일부러 넣은 15개 발화로 인한 중단은 일반 음성 출력 장애에 합산하지 않았다.
이번 반복 실행에 대한 별도의 사람 청취 품질 판정은 받지 않았다. 이전 비중단
10초·20초 안내의 청취 확인은 [이전 보고서](android-working-memory-validation.md)에 있다.

## 해석과 다음 개선 지점

1. “십 초” 인식 오류는 5회 모두 재현된다. 현재 합성 입력과 ASR 조합의 숫자 인식
   문제이며, 이를 임의로 10초로 치환해 점수를 올리지 않았다.
2. 샐러드 요청은 5회 모두 정확히 인식됐는데 답변이 실패했다. 이 실패를 ASR 탓으로
   볼 수 없다. 응답 생성과 문맥 구성의 별도 개선·비교 검증이 필요하다.
3. 원본 상태에서 샐러드 질문 이후에도 목표가 `20초 타이머`로 남아 있는 것을
   5회 관측했다. 완료된 작업에서 새 요청으로 넘어가는 처리가 답변에 영향을 줄
   가능성은 있으나, 이번 고정 측정만으로 원인을 확정하지 않는다.
4. 후속 안내의 발언권·중단·보류·전달 완료·중복 방지는 이 시나리오에서 반복성을
   확인했다. 이를 범용 에이전트나 전체 Live 사용성 합격으로 확대하지 않는다.

## 실행 환경·검증 근거

external-dev doctor는 실행 전 RTX3090 24GB 두 장과 여유
20,998MiB / 24,108MiB를 확인했다. 실제 모델 추론은 태블릿에서만 수행했다.
다른 프로젝트/프로세스, 환경, GPU 작업은 변경하지 않았다.

- ASR: Qwen3-ASR-0.6B `5eb144179a02acc5e5ba31e748d22b0cf3e303b0`
- VLM: Qwen3.5-4B `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`
- MNN: `9f097c5fdd48e0cac4468d4cc53a828794d96888`
- 기존 모델 bundle/런타임 patch는 [이전 검증](android-working-memory-validation.md)의
  manifest와 동일하다. 음성 합성은 설치된 오프라인 TTS이며 Qwen TTS 성능 측정이 아니다.
- 평가 APK SHA256: `254b42a58657e5211e7f163e884a0b3316df0793ce2f8fb671b95802581121b9`.
  debug 평가 실행부만 추가했다. 제품/공통 코어/모델 설정29개 파일의 실행 전후 hash가 같았다.
- `assembleDebug`, `lintDebug`, `git diff --check` 통과. 제품 동작 변경이 없으므로 기존
  CPU52 통과를 이번 실행에서 다시 얻었다고 주장하지 않는다.
- 집계는 첫 실측 회차와 대조했고, 다른 답변에 과거 평가를 재사용하는 hash 불일치도 거부했다.


보존하고, 기존 실패 실행을 덮어쓰거나 새 성공만 합쳐 비율을 계산하지 않는다.
